# VHS-90 — NTSCRT Physical VCR / Receiver Engine Audit

Date: 2026-11-19
Input: `vhs/github repos/NTSCRT-0.26.0/` from supplied `vhs.zip`.
Scope in this checkpoint: README and development architecture, the physical VCR model (`Tape.swift`, `Deck.swift`, `Transport.swift`, `VcrStage.swift`), receiver/glitch model (`Receiver.swift`, `GlitchParams.swift`, `GlitchStage.swift`), Windows Rust/wgpu port's corresponding tape/deck/transport/VCR modules, parameter schema, and parity-test structure. The archive has 323 files; this is a focused engine audit, not a claim that every SwiftUI view, codec, shader preset, asset and app-support file has been fully reviewed.

## Overall architecture

The source describes a signal chain with distinct physical and display stages:

`source → crop → optional digital camera/codec → NTSC composite signal → downscale → physical VHS tape/deck → simulated TV receiver/glitches → CRT display shader`

For VHS-90, the highest-value material is the physical tape/deck model and its signal-record/playback stage. The Digital video, Screen Loop, timeline, app UI and CRT display shader systems are separate features and are not prerequisites for the VHS-90 effect.

The project is explicit that it does not draw static/glitch overlays to imitate the VCR: its tape surface, heads, transport and receiver circuits generate the output.

## 1. Physical tape geometry and format

The VCR simulation uses NTSC VHS SP reference geometry:

- Tape width: 12.65 mm.
- Slanted track angle: 5.97°.
- Video head writing speed: 5.8 m/s.
- Track starts near the bottom reference edge and rises across the tape.
- Track geometry maps tape height across the tape to picture height.
- SP, LP and EP move the tape by progressively smaller amounts between fields.
- Neighboring track pitches: approximately 58 µm (SP), 29 µm (LP), 19.3 µm (EP).
- SP head width: 58 µm; LP/EP four-head width: 26 µm.
- Track line offsets: 1.5 lines SP, 0.75 LP, 0.5 EP.
- A head reads contributions from its own track and two neighboring tracks.
- Alternating heads use opposite azimuth angles; the short-wavelength FM picture signal is cancelled much more strongly than the longer color-under signal when reading a neighboring track.

The format therefore changes actual track overlap, crosstalk, noise and tolerance to tracking error; it is not merely a preset label.

## 2. Procedural tape surface

The tape is a seeded, spatially persistent material map. Its flaws are generated by tape-position cells, so the same physical defect is read again when the head returns to that position.

The surface returns four separate physical values:
- Lift: distance holding the tape away from the head.
- Film: a surface film such as Vaseline.
- Output: remaining magnetic coating / magnetization.
- Shed: material transferred from the tape to the heads.

Implemented defect families include:
- Pinhole loss in the magnetic coating.
- Larger flakes / missing oxide.
- Lengthwise scratches, with local weave and depth.
- Creases across the tape; the fold shortens the recorded track and creates a time-base jump.
- Crinkled top and bottom tape edges.
- Edge-biased mold colonies that lift the tape, damage coating and shed material.
- Vaseline streaks with local film thickness.
- Base wear and roughness.

The same tape-position hashing and material map are mirrored in the Metal and WGSL implementations. The test suite includes a CPU/GPU tape-surface parity test.

## 3. Two-head deck model

The deck simulates two independently aged heads, one per field:
- Head wear changes spacing, efficiency and gap width.
- Head mismatch ages the two heads unevenly, so alternating fields can have visibly different quality.
- Baseline dirt is independently distributed per head.
- Tape shedding contributes debris pickup.
- Debris builds up, sometimes lodges as a clog, and sometimes knocks loose.
- Vaseline transfers to the heads quickly and wipes off slowly.
- The state advances field-by-field and supports snapshots/restores.

This provides a much more grounded mechanism for alternating-field defects than applying a simple frame-wide flicker.

## 4. Tape transport and tracking servo

The transport is modeled line-by-line:
- A control-track pulse is read once per frame from the tape's bottom edge.
- A type-2 capstan servo (approximately 1.4 Hz) corrects tape speed and position.
- Missing/damaged control pulses let the transport drift.
- Crinkles can create false pulses and kick the servo.
- Back tension stretches or slackens the tape and changes time-base error.
- Three guide points simulate stick-slip: tape lags while stuck, then tears loose and overshoots.
- Drum flutter and pinch-roller wobble add faster timing variation.
- Search mode disables normal servo tracking and sweeps the heads across multiple tracks.
- The model calculates time-base error from track pitch, transport offset, tension, folds and prior dub generations.

The physical Tracking control is a tape-position/servo offset. It does not provide arbitrary image-space X/Y/width/height placement. VHS-90 must expose the requested custom-region Tracking Noise module separately from the physical tracking servo, or add a user-defined region mask around its output.

## 5. VHS record/play signal path

The VCR stage processes the signal at 1,820 samples per line (8× the color subcarrier):

1. Convert input RGB to YIQ.
2. Record luma using pre-emphasis, clipping and FM carrier modulation (approximately 3.4–4.4 MHz).
3. Record chroma as a color-under QAM carrier at 40 times the line frequency.
4. Look up the tape surface at multiple points across each head segment.
5. Apply magnetic coating output, surface lift, film and shedding.
6. Combine the center and neighboring tracks according to head overlap and azimuth loss.
7. Apply spacing loss and head-gap aperture filtering, with per-head kernel banks.
8. Add head/preamp noise.
9. Apply an analytic FM band-pass.
10. Demodulate FM into luma, then apply zero-phase luma low-pass and de-emphasis.
11. Detect dropouts by comparing the FM envelope to its own recent peak, so sudden signal loss is distinguished from a uniformly weak signal.
12. Mix down and low-pass the color-under carrier.
13. Apply line comb filtering to cancel neighboring-track chroma at the cost of vertical color detail.
14. Recover burst phase and gain with ACC/APC and color-killer behavior.
15. Reconstruct pixels and optionally compensate dropouts by repeating an earlier line.

The spacing loss is frequency-dependent: it damages the short-wavelength FM picture far more than the lower-frequency color-under signal. This is a strong basis for VHS-90's characteristic “picture breaks into noise while color smears on” look.

## 6. Copy generations

A copied tape is not approximated by increasing a noise slider. The model re-records and replays through earlier deck generations:
- Each earlier generation is a complete VCR field plan.
- Composite picture and color are separated again by the recording deck.
- Luma and chroma are filtered, delayed and can become slightly misaligned.
- Each copy accumulates detail loss, noise and timing errors.

This is an optional high-cost feature for VHS-90, but it is a distinctive physical mechanism worth preserving as a later advanced mode.

## 7. TV receiver and static/signal failure

The receiver stage models actual synchronization and color-recovery circuits:
- Horizontal AFC phase-locked loop with proportional/integral correction and limited VCO range.
- Vertical relaxation oscillator / injection locking.
- Sync separator noise, missed pulses and false triggers.
- Horizontal hold can slide and then tear the picture.
- Vertical hold can lose lock and roll the picture with a blanking bar.
- Burst gate, color phase loop, ACC and color killer.
- Multipath ghosting with delayed and possibly inverted signal and color-phase rotation.
- 60 Hz hum bars and picture bending.
- Snow is generated as luma plus bandwidth-shaped I/Q chroma noise.
- Caption data can appear in line 21 when the picture rolls.

The stage's default healthy state is an exact input bypass. Its glitches arise from receiver response, not from drawing overlay graphics.

## 8. Head switching: physical model versus VHS-90 requirement

The source models physical head switching as a timing jump when the deck changes heads just before vertical sync. The bottom lines jump sideways and the TV's AFC follows that jump into the top of the next field, producing flagging.

That physical mechanism is valuable and should be preserved as a timing/sync event. However, it does **not** expose a user-controlled arbitrary vertical region or a height slider that can expand from the bottom to the entire frame. VHS-90's required Head Switching module must add a separate region geometry layer (position, height, intensity and behavior) while optionally retaining the authentic physical timing-jump model underneath.

Similarly, the source's control-track servo is anchored to the tape's bottom edge by VHS geometry. VHS-90's user-facing Tracking Noise requirement is broader: custom position anywhere in the frame, custom width/height, direction and multiple independent regions. Do not silently equate the physical servo control with the user's arbitrary-region Tracking Noise control.

## 9. Determinism, random access and MFR concepts

- Tape defects are hash-based from cassette seed and tape coordinates.
- Head dirt/debris events are keyed by field.
- Transport and receiver simulation depend on settings over time and seed.
- Receiver and deck state support snapshots/restores.
- Receiver can resimulate from a saved state to a target time.
- The Windows port has parity tests comparing its field plans against Mac-generated fixtures.
- This is a useful model for deterministic random-access rendering and MFR: all evolving state must be render-context-local and reconstructible from frame/time/seed, not stored in global mutable RNG state.

## 10. Native shader / Windows port

- The Mac VCR and receiver pixel stages are Metal compute kernels embedded in Swift source.
- The Windows port translates the engine and kernels to Rust + WGSL + wgpu.
- The Windows port's own README states it is a separate Rust/wgpu implementation; the Mac app remains Swift/Metal.
- The VCR and receiver output kernels currently write alpha as 1.0. VHS-90 must not copy this behavior; preserve the original AE alpha and process premultiplied color safely.
- The Windows port includes tests for receiver plan parity, preview determinism, thread preparation and glitch behavior, plus field-plan fixtures.

## VHS-90 integration decision

Treat this as the strongest reference in the supplied bundle for physically grounded tape, deck and transport behavior. Port the physical equations and deterministic material model into VHS-90's CPU-first C++ engine; keep the signal recording/playback model modular so it can be enabled as a high-fidelity VHS stage. Build a separate arbitrary-region engine for the user's Tracking Noise and Head Switching controls, preserve alpha, and move all evolving state into an explicit per-render context suitable for AE Multi-Frame Rendering.
