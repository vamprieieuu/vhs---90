VHSart — DIAGONAL SYNC COLLAPSE

Hybrid Procedural Engine — VHS DAMAGE LAB

1. Objective

Implement a dedicated hybrid procedural effect preset named:

Diagonal Sync Collapse

Use the supplied video_1.mp4 as the primary visual reference.

Reconstruct its distinctive combination of:

  1. A sudden full-frame diagonal signal-collapse event.
  2. Strong diagonal shear and fragmented multicolored signal bands.
  3. Horizontal chroma smearing around high-contrast image details.
  4. Intermittent transitions between neutral gray and saturated blue signal states.
  5. Subtle analog softness, grain, scanline interruptions, and signal instability.

This is not a conventional VHS filter. Its identity comes from the sudden diagonal synchronization failure, followed by a relatively stable blue/gray signal state with persistent chromatic distortion.

The engine must work on ordinary footage while also supporting a generated-signal mode that can reproduce the reference’s visual appearance independently of source footage.

2. Mandatory Project Inspection

Before implementation:

  • Inspect the complete VHSart project structure.
  • Locate VHS DAMAGE LAB and its existing processing engines.
  • Inspect existing diagonal distortion, image displacement, chroma separation, horizontal smear, blue/gray color processing, grain, static, scanline, and dropout implementations.
  • Reuse existing engines wherever possible.
  • Extend existing functionality instead of creating duplicate algorithms.
  • Build only the missing specialized functionality.
  • Preserve existing presets, controls, rendering behavior, and project architecture.

The recommended architecture is hybrid:

Existing VHSart engines: softness, analog grain, horizontal chroma smear, scanline/dropout processing, and general color processing.

New dedicated engine: Diagonal Shear & Synchronization Collapse, including the event trigger, diagonal band fragmentation, and event-specific chromatic disruption.

Do not create separate redundant engines for features already supported by the project.

3. Primary Engine — Diagonal Shear & Sync Collapse

Implement a specialized procedural engine responsible for the sudden diagonal signal failure.

A. Diagonal Shear Geometry

Reconstruct the reference’s diagonal bands and fragmented image geometry.

Visual characteristics:

  • Strong diagonal cuts across the frame.
  • Multiple slanted bands with irregular boundaries.
  • Abrupt horizontal and diagonal discontinuities.
  • Variable displacement between neighboring bands.
  • Alternating regions of displaced image information.
  • Irregular band widths and spacing.
  • Stronger geometric disruption during the collapse event.

Implementation requirements:

  • Use coordinate transformation and inverse sampling.
  • Support adjustable diagonal angle and displacement.
  • Divide the image into diagonal regions using transformed coordinates.
  • Apply independent displacement to individual regions.
  • Introduce controlled irregularity into band boundaries.
  • Support multiple simultaneous diagonal bands.
  • Allow individual bands to have different displacement magnitudes and directions.
  • Add optional horizontal interruptions within diagonal bands.
  • Support channel-specific displacement during the event.

Use normalized coordinates so the effect remains consistent across different frame dimensions and aspect ratios.

A possible starting coordinate transformation is:

u = x * cos(theta) + y * sin(theta)

Use the transformed coordinate to identify diagonal bands and their boundaries.

The implementation must use appropriate inverse mapping and sampling to avoid unintended holes or unstable pixel access.

B. Chromatic Collapse

The diagonal event must produce a distinctive chromatic breakdown.

Visual characteristics:

  • Highly saturated green, purple, magenta, blue, yellow, and red regions.
  • Strong color separation between adjacent diagonal bands.
  • Irregular RGB channel displacement.
  • Local chroma fragmentation.
  • Horizontal color streaks within displaced regions.
  • Abrupt transitions between saturated colors and dark/light interruptions.

Implementation requirements:

  • Support independent R, G, and B displacement.
  • Support different displacement directions per channel.
  • Introduce band-dependent color variation.
  • Control chroma intensity independently from geometric displacement.
  • Support saturated color bursts during the collapse event.
  • Allow color fragmentation without necessarily displacing the entire image geometry.
  • Avoid turning the result into a simple RGB split effect.

4. Event Trigger & Temporal State System

This is one of the most important parts of the reconstruction.

The reference does not show continuous maximum-intensity diagonal distortion. It shows a sudden, short-lived collapse followed by a comparatively stable signal state.

Build a proper event system with independently adjustable timing and duration.

Required controls:

  • Collapse Enable
  • Collapse Trigger
  • Collapse Intensity
  • Collapse Duration
  • Collapse Frequency
  • Collapse Probability
  • Event Randomness
  • Event Recovery
  • Random Seed

Support three trigger modes:

Manual / Keyframed

  • The user controls the event through keyframes or the trigger parameter.
  • The event can be positioned precisely on the After Effects timeline.

Automatic / Procedural

  • Events occur according to adjustable timing and probability.
  • Each event has a controllable intensity and duration.

Seeded / Deterministic

  • Event timing and appearance are generated reproducibly from the Seed and frame time.

Important temporal requirements:

  • Support sudden onset.
  • Support a short peak-intensity phase.
  • Support optional partial recovery.
  • Allow abrupt termination when appropriate.
  • Avoid unnecessary smooth fades if the reference calls for an abrupt signal failure.
  • Do not change the entire effect randomly on every rendered frame.
  • The same Seed, frame, and settings must always produce the same output.

Do not hardcode the event to 00:00.250. That timestamp describes the supplied reference, not a universal operating rule.

5. Blue / Gray Signal State Engine

After the diagonal collapse, the reference transitions between neutral gray and saturated blue/indigo states.

Reconstruct this behavior as a separate color-state component.

Required visual characteristics:

  • Neutral gray signal state.
  • Saturated blue/indigo signal state.
  • Cyan-blue chromatic variation.
  • Intermittent transitions between the two states.
  • Subtle luminance and contrast variation.
  • Horizontal chroma smearing around high-contrast features.

Required controls:

  • Signal Color State
  • Blue Cast Amount
  • Blue Saturation
  • Blue Channel Gain
  • Gray State Amount
  • State Transition Speed
  • State Transition Randomness
  • Color Instability
  • State Random Seed

Provide the following modes:

  • Original Colors
  • Neutral Gray
  • Blue Signal
  • Gray / Blue Intermittent
  • Procedural Color State

The Blue / Gray Intermittent mode must support abrupt or irregular transitions rather than forcing a continuous blue gradient.

The color-state engine must not require the diagonal collapse to remain active.

6. Horizontal Chroma Smear

Reuse the existing VHSart chroma-smear engine if it already supports the required behavior.

Otherwise, extend it with the missing functionality.

Reconstruct:

  • Horizontal color spreading around text and high-contrast edges.
  • Independent chroma displacement.
  • Short and medium horizontal color streaks.
  • Subtle RGB separation.
  • Localized chromatic bleeding.
  • Greater chroma disruption during diagonal collapse.
  • Lower chroma intensity during stable blue/gray states.

Required controls:

  • Horizontal Chroma Smear
  • Smear Length
  • Smear Intensity
  • RGB Separation
  • Chroma Offset
  • Chroma Softness
  • Edge Sensitivity
  • Event Chroma Boost

The smear must operate on image information and must not become an arbitrary full-frame colored blur.

7. Analog Base & Supporting Artifacts

Use existing VHSart processing engines for the supporting analog appearance.

Required components:

Soft Low-Resolution Base

  • Adjustable softness.
  • Optional resolution degradation.
  • Controlled high-frequency detail reduction.

Analog Grain

  • Fine luminance grain.
  • Optional chroma grain.
  • Adjustable intensity and temporal variation.

Horizontal Scan / Dropout Lines

  • Thin irregular horizontal interruptions.
  • Short bright and dark streaks.
  • Occasional signal discontinuities.
  • Independent density and intensity.

These components should remain subtle during stable states and may become stronger during the diagonal collapse.

Do not introduce heavy tracking damage, excessive snow, or unrelated VHS artifacts that are not visible in the reference.

8. Processing Architecture

Use the following logical processing order:

  1. Input validation and source-format handling.
  2. Optional softness and low-resolution processing.
  3. Analog grain and supporting signal texture.
  4. Temporal event-state evaluation.
  5. Diagonal shear and band segmentation.
  6. Event-dependent RGB and chroma disruption.
  7. Horizontal chroma smear.
  8. Blue/gray signal-state color processing.
  9. Horizontal dropout and scanline interruptions.
  10. Final compositing and Alpha handling.

The implementation may optimize or combine stages where mathematically appropriate, but it must preserve the intended visual dependencies and processing order.

9. Compositing Modes

Provide:

Effect Mode

  • Apply to Original Footage
  • Generated Signal
  • Hybrid Signal Reconstruction

Blend Amount

Controls the contribution of the processed result.

Original Image Contribution

Controls how much original image information remains visible.

In Generated Signal mode, the engine must be able to create a complete signal-like visual output without relying on recognizable source footage.

In Apply to Original Footage mode, geometric displacement must operate on the actual input image.

Do not generate the reference’s text (A. TRACKING, SP, or CIRCULAR MOTION) as fixed graphic elements. These are reference-image content, not part of the effect engine.

13. Technical Requirements

The effect must remain a genuine native C++ After Effects plugin.

Requirements:

  • Follow the existing project’s AE SDK and build configuration.
  • Maintain consistent effect version and PiPL version information.
  • Preserve existing parameter registration conventions.
  • Support the bit depths already supported by VHSart.
  • Correct Alpha handling.
  • Correct premultiplied-alpha processing.
  • Multi-Frame Rendering compatibility.
  • Thread-safe rendering.
  • No shared mutable global rendering state.
  • Deterministic temporal evaluation.
  • Safe memory management.
  • CPU-first implementation.
  • No external runtime dependencies.

When geometric transformations are applied to transparent input, sample and process Alpha consistently with the image data. Do not introduce black fringes or incorrect premultiplied RGB values.
